# ResolveNodeKit agent entrypoint

Build compact, reversible Fusion and Color workflow tools for DaVinci Resolve. This is not an Auto-Node-Tree fork or a Blender Node Wrangler port.

## Authority and current route

Current user instruction > live Git/PR/runtime evidence > `docs/CURRENT_STATE.md` > applicable repo contracts > current installed/primary documentation > historical notes > inference.

The current product mission is **v1 Automatic Node Arrange / Preserve**. Start with `docs/PRODUCT_DIRECTION_BRIEF.md`, then `docs/execution/v1-arrange/README.md`, `PLAN.md` and `acceptance.json`. The official v1 user workflow is:

```text
Arrange -> optional Resolve native GUI manual Ungroup -> Re-Arrange
```

Manual Ungroup is an intentional v1 product boundary. Automatic Ungroup / Flatten All is v2 and must not be presented as a normal v1 feature. The old `docs/execution/strict-orthogonal/` contract and the dated `docs/execution/semantic-arrange-v1/` continuation remain preserved as v2/research/historical evidence; they are not current v1 release authority.

For Resolve host work, use **direct guarded execution by the capable Product Worker**. The historical dedicated/external Resolve Operator and WP1 semantic-receipt path are research-only and are not product dependencies. Keep only the smallest mechanical Host Guard needed for the operation.

Inspect local Git status before pull/checkout/rebase. Preserve unknown dirty work and live worker/host leases. Historical project/timeline names, counts, process IDs and SHAs are locators, not fresh target identity.

Other applicable contracts remain `docs/GROUPS.md`, `docs/COLOR_API.md`, `docs/HOST_VALIDATION.md`, `docs/EVIDENCE_PROTOCOL.md`, `docs/ORCHESTRATION.md` and the semantic-layout design docs.

## Invariants

- Preserve actual port-labelled processing connections, parameters, keyframes, expressions, instances and media. Layout projection is not permission to rewire processing.
- v1 Arrange preserves every `GroupOperator`, direct parent/child membership and tool identity. It never performs automatic Ungroup or Flatten All.
- Automatic Ungroup, `UngroupFirst`, Flatten All and flatten-specific processing/render qualification belong to v2. A fail-closed v2 wrapper is not v1 product surface or v1 completion proof.
- Do not use guessed APIs/actions, names, current XY or screenshot appearance as processing-graph truth. Missing reads are not empty/unconnected data.
- Host mutation follows exact target bind, complete snapshot, pure planning, bounded writes, actual readback, verification and rollback on mismatch. Never retry an ambiguous write before reconciling its outcome.
- One integration/state writer and one exclusive Resolve host writer/serialization boundary for mutable work. Fresh verifier does not repair its own candidate.
- Test narration, mocks, direct controller execution and UI visibility each prove different things. Keep exact candidate, coverage and evidence scope explicit.
- Fusion and Color adapters remain separate. Do not assume a Fusion method exists in Color.

## Authorized work / boundaries

Task-branch code/tests/docs, backup-backed install, commit/push and Draft PR #5 updates are authorized. Direct Resolve MCP/scripting/GUI operations, Resolve launch/quit/restart, owned disposable fixtures and reversible validation mutations are authorized under the current runbook. No valuable project save, main merge, actual release/tag, force-push, credential change, unrelated deletion/process kill, PC reboot, global shortcuts, permanent services/startup or unsupported blind UI operations.

## Completion and learning

A v2 or host-surface blocker does not stop independent v1 Arrange work. Do not declare completion by counting repeated blockers, deleting v1 criteria, or relabelling unsupported behavior as PASS. Keep v1 release-candidate status separate from the broader ResolveNodeKit `MISSION_COMPLETE` and from the preserved strict G01–G14 research contract.

After meaningful changes: run focused tests, perform required host evidence, execute the lightweight Learning Gate, update the durable checkpoint/state, reconcile PR metadata, and read back the remote ref. Do not add a generic orchestration framework merely to operate this project.
